# Локальный Whisper (транскрибация голоса для Make)

Self-hosted сервис распознавания речи на базе `faster-whisper`. Принимает аудиофайл
по HTTP и возвращает текст. Предназначен для транскрибации голосовых сообщений из
Telegram внутри сценария Make, без подписки на OpenAI.

Образ: `onerahmet/openai-whisper-asr-webservice` (движок `faster_whisper`).

---

## Требования

- Docker + Docker Compose v2.
- ~1–3 ГБ RAM под выбранную модель (см. таблицу) и несколько ядер CPU на время запроса.
- GPU не нужен.

## Запуск

```bash
# Положите compose.yaml в отдельную папку и запустите:
docker compose up -d

# Логи (первый старт качает модель — это разово):
docker compose logs -f whisper
```

Первый запрос будет дольше: модель скачивается и загружается в память. Дальше она
кэшируется в томе `whisper-cache`, а после простоя выгружается (`MODEL_IDLE_TIMEOUT`).

## Выбор модели

Меняется через `ASR_MODEL` в `compose.yaml`. Для русского языка на CPU:

| Модель    | RAM (int8) | Скорость на CPU | Качество для русского |
|-----------|-----------|-----------------|-----------------------|
| `tiny`    | ~0.5 ГБ   | очень быстро    | низкое                |
| `base`    | ~0.7 ГБ   | быстро          | среднее               |
| `small`   | ~1 ГБ     | умеренно        | хорошее (рекомендую)  |
| `medium`  | ~2.5 ГБ   | медленно        | очень хорошее         |
| `large-v3`| ~4–5 ГБ   | заметно медленно| лучшее                |

Старт с `small`. Если качество распознавания русского не устроит — поднимите до
`medium`. Голосовые из Telegram короткие, так что даже `medium` на CPU обычно
отрабатывает за несколько секунд.

После смены модели:

```bash
docker compose up -d
```

## Проверка (curl)

Эндпоинт: `POST /asr`. Файл передаётся как `multipart/form-data`, поле `audio_file`.
Параметры задаются в query-строке.

```bash
curl -F "audio_file=@voice.oga" \
  "http://127.0.0.1:9000/asr?encode=true&task=transcribe&language=ru&output=txt"
```

- `encode=true` — сервис сам перекодирует вход через ffmpeg, так что формат Telegram
  (`.oga`, Opus в Ogg) принимается без подготовки.
- `task=transcribe` — распознать как есть (для перевода на английский было бы `translate`).
- `language=ru` — можно убрать, тогда язык определится автоматически (чуть медленнее).
- `output=txt` — вернёт чистый текст. Для структурированного ответа: `output=json`.

В браузере по адресу `http://127.0.0.1:9000` доступна Swagger-документация с
возможностью протестировать запрос вручную.

## Подключение в Make

В сценарии после Telegram нужно сначала скачать файл, потом отправить его в Whisper.

1. **Telegram Bot → Download a File** — по `file_id` голосового сообщения
   (`message.voice.file_id`). На выходе получите бинарные данные файла.

2. **HTTP → Make a request**:
   - **URL**: `https://whisper.ваш-домен/asr` (через reverse proxy, см. «Безопасность»).
   - **Method**: `POST`
   - **Query String**: `task=transcribe`, `language=ru`, `output=txt`, `encode=true`.
   - **Body type**: `Multipart/form-data`
   - Добавьте поле типа **File**: имя `audio_file`, значение — данные из шага Download a File.
   - **Headers**: токен авторизации вашего прокси (см. ниже).
   - **Parse response**: можно `No` — при `output=txt` ответ и так чистый текст.

3. Текст из ответа HTTP-модуля передаёте дальше в переменную `user_text` —
   ту же, в которую кладётся текст из текстовой ветки роутера.

Так обе ветки (текст / голос) сходятся к одному нормализованному входу для агента.

## Безопасность (обязательно прочитать)

Сервис **не имеет встроенной авторизации**. На сервере с белым статичным IP нельзя
публиковать порт 9000 наружу — иначе любой сможет грузить в него аудио и тратить
ваши ресурсы (а то и эксплуатировать уязвимости).

Поэтому в `compose.yaml` порт привязан к `127.0.0.1`. Доступ снаружи (для облака Make)
организуйте через ваш существующий reverse proxy:

- Заведите поддомен (например, `whisper.ваш-домен`) и проксируйте его на
  `127.0.0.1:9000`.
- Включите проверку секрета: basic-auth или заголовок-токен
  (например, `Authorization: Bearer <длинный_случайный_токен>`), который проверяет
  прокси и режет всё остальное.
- В Make добавьте этот же заголовок в HTTP-модуль.

Если reverse proxy ещё нет — это разовая настройка на уровне вашего обычного стека
(Nginx Proxy Manager / Traefik / Caddy), и она же закроет вопрос TLS.

## Эксплуатация

```bash
docker compose ps          # статус
docker compose logs -f whisper   # логи
docker compose pull && docker compose up -d   # обновление образа
docker compose down        # остановить (том с моделью сохранится)
```

Ресурсы: модель загружается в RAM только на время работы и выгружается после
`MODEL_IDLE_TIMEOUT` секунд простоя. Лимиты `cpus` и `mem_limit` в `compose.yaml`
не дают сервису забить сервер в момент запроса — подберите их под свой CPU.

## Возможные проблемы

- **Первый запрос долгий / таймаут в Make** — идёт скачивание модели. Прогрейте
  один раз через curl, затем настраивайте Make.
- **`MODEL_IDLE_TIMEOUT` не применяется** — переменная есть не во всех версиях
  образа; просто уберите её, на работу это не влияет.
- **Плохое качество русского** — поднимите `ASR_MODEL` до `medium`.
- **Make не достучался** — проверьте, что запрос идёт через reverse proxy с
  токеном, а не напрямую на `127.0.0.1` (этот адрес доступен только на самом сервере).
